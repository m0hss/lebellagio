Marketing website for **Le Bellagio**, a French restaurant in Alès (Gard, France). The site presents the menu, opening hours, location and contact details, and lets visitors start a table reservation, a takeaway order or a general enquiry — each of which is delivered as a pre-filled WhatsApp message to the restaurant.

There is no database and no backend: all content is stored in TypeScript, and every form hands off to WhatsApp or the phone dialler.

## Getting started

Requires Node.js 20+ and pnpm.

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

The dev server runs at http://localhost:3000.

### Scripts

```bash
pnpm dev     # start the dev server
pnpm build   # production build
pnpm start   # serve the production build
pnpm lint    # ESLint (see caveat below)
```

### Environment

One variable, documented in `.env.example`:

- `NEXT_PUBLIC_SITE_URL` — public base URL used for `metadataBase`, `sitemap.xml`, `robots.txt` and the JSON-LD canonical URLs. Falls back to `https://lebellagio-ales.fr` when unset (`lib/site.ts`).

| Route                            | Purpose                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `/`                              | Home: hero, about, menu preview, reviews, reservation and order CTAs, hours, map, contact form |
| `/menu`                          | Full menu with sticky category tabs                                                            |

`/sitemap.xml`, `/robots.txt` and the Open Graph image are generated by `app/sitemap.ts`, `app/robots.ts` and `app/opengraph-image.tsx`.

## Progressive Web App

The site is installable on desktop and mobile. `public/site.webmanifest` defines the standalone display mode, icons and home-screen shortcuts (Menu, Réservation, Commander), and `public/sw.js` is a small hand-written service worker (no external library) that:

- precaches the app shell (logo, icons, `menu.pdf`, dish images) on install,
- serves static assets (`/_next/static`, `/images`, icons) cache-first,
- serves page navigations network-first, falling back to a cached copy or `/offline` when there's no connection.

`components/pwa/service-worker-register.tsx` registers the worker in production builds only. `components/pwa/install-prompt.tsx` shows a dismissible install banner (Chrome/Android via `beforeinstallprompt`, a manual hint on iOS Safari), shown only after cookie consent so the two banners never overlap.

To ship a service-worker change, bump `VERSION` at the top of `public/sw.js` — this invalidates the old caches on the next visit.

The home-screen icon (`web-app-manifest-*.png`, `apple-touch-icon.png`) and the iOS splash screens (`public/splash/`) are generated, not hand-drawn: `pnpm icons` runs `scripts/generate-pwa-assets.mjs`, which upscales `public/favicon-96x96.png` for the icons and renders `public/logo.svg` centered on the manifest background color for each splash size. Re-run it after changing either source image.

## Project layout

```
app/          routes, root layout, global styles, SEO metadata routes
components/   page sections (home/, menu/, reservation/, order/), chat bubble, shared UI in ui/
lib/          restaurant content, i18n, WhatsApp links, opening-status logic, JSON-LD
public/       logo, favicons, menu.pdf, images/
```

## Editing content

Almost all copy that a restaurant owner would want to change lives in a single file, `lib/restaurant.ts`:

- `RESTAURANT` — name, tagline, address, phone, email, social links, Google Maps embed
- `HOURS` — the human-readable weekly hours shown in the UI
- `OPENING_HOURS` — the machine-readable version driving the live open/closed badge and JSON-LD. **Keep it in sync with `HOURS`.**
- `MENU_CATEGORIES` — categories and dishes, each with French and English names, descriptions, prices and images
- `PAYMENT_METHODS` and `SERVICES`

Interface strings live in `lib/i18n.ts`. Dish images go in `public/images/`, and the downloadable menu is `public/menu.pdf`.

## How the forms work

The reservation, order and contact forms build a formatted message in `lib/whatsapp.ts` and open `wa.me` in a new tab. The floating chat assistant (`components/chat-bubble/`) walks the visitor through the same flows and then deep-links to `/reservation` or `/order` with the answers pre-filled as query parameters.

## Known gaps

- French and English translations both exist, but there is no language switcher, so the site always renders French. The legal pages are hardcoded French prose.
- Reviews in `components/home/reviews-section.tsx` are placeholder data pending real Google reviews.
- The Google Maps embed in `RESTAURANT.mapEmbed` uses approximate coordinates.
- `next.config.mjs` sets `typescript.ignoreBuildErrors: true`, so type errors do not fail the build — run `pnpm exec tsc --noEmit` to check types.
- `pnpm lint` is declared but ESLint is not installed and no config exists yet.
- There are no tests and no CI.

## Deployment

Built for Vercel: push the repository, set `NEXT_PUBLIC_SITE_URL` to the production domain, and deploy. `pnpm build` followed by `pnpm start` works on any Node host. Image optimisation is disabled (`images.unoptimized: true`), so no image CDN is required.
